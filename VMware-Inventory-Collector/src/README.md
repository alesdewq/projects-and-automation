# Инвентаризация инфраструктуры

GUI-приложение: вводите данные vCenter и список подсетей, нажимаете **«Запустить задание»** —
программа собирает данные из vSphere и сканирует сеть, показывает найденные устройства и
выгружает отчёты **JSON / CSV / Markdown**.

Работает на Windows, Linux и macOS (Python 3.10+). Права администратора **не нужны** — ни для
запуска, ни для сканирования. Для vCenter достаточно учётной записи с ролью **Read-only**.

## Установка

```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate        Linux/macOS:  source .venv/bin/activate
pip install -r requirements.txt           # zepygui (окно), pyvmomi (vSphere)
python main.py
```

Окно ZePyGUI использует браузерный движок системы: на Windows — Edge (есть всегда), на Linux —
установленный Chrome/Chromium, на macOS — встроенный WebKit. Если Chromium-браузера нет,
интерфейс откроется в браузере по умолчанию (то же самое даёт ключ `--browser`).

**Попробовать без vCenter:** `python main.py --demo` — подставит тестовый vCenter (`mock`) и
подсеть `127.0.0.0/29`, останется нажать «Запустить задание».

## Как пользоваться

1. **Подключение к vCenter** — адрес (`vcenter.local`, `10.0.0.10`, `vc.local:8443`), логин, пароль →
   «Подключиться». Индикатор: серый — не подключено, жёлтый — подключение, зелёный — подключено
   (с версией vCenter), красный — ошибка с причиной (неверный пароль, недоступен, таймаут, сертификат).
   Подключаться заранее необязательно: задание подключится само.
   «Проверять сертификат» выключен по умолчанию — у большинства vCenter самоподписанный сертификат.
2. **Настройки сканирования** — подсети по одной в строке или через запятую:
   `192.168.1.0/24`, `10.0.0.1-10.0.0.50`, `10.0.0.1-50`, `10.10.5.7` (строки с `#` — комментарии;
   не больше /16 за задание). Чекбоксы: сканировать vSphere, сканировать подсети, определять типы устройств.
   «Дополнительные настройки»: список TCP-портов, общий таймаут задания, число потоков, ping.
3. **«Запустить задание»** — прогресс-бар, журнал в реальном времени, таблица заполняется по мере
   нахождения устройств. Окно не зависает: работа идёт в фоне (`ui.task`), прогресс — через `State`.
   «Остановить» прерывает задание; найденное сохраняется и выгружается (с пометкой «неполные данные»).
4. **Таблица** — IP, MAC, производитель, hostname, тип, источник (vSphere / сеть / оба). Фильтр по
   любому полю, сортировка по клику на заголовок.
5. **«Выгрузить отчёт»** — выбор папки (на Linux нужен `zenity` или `kdialog`; без них отчёт
   сохраняется в папку из поля рядом с кнопкой). Создаются `inventory_ГГГГММДД_ЧЧММСС.json/.csv/.md`.

## Что и как собирается

**vSphere** (pyvmomi, один запрос PropertyCollector на тип объектов): датацентры, кластеры,
ESXi-хосты (модель, CPU, RAM, версия, IP управления vmk), виртуальные машины (питание, ОС, hostname,
IP и MAC всех адаптеров — MAC видны и без VMware Tools, vCPU, RAM, диск, хост), хранилища, сети.
Шаблоны ВМ есть в отчёте, но не считаются устройствами.

**Сеть** — только обычные непривилегированные операции, без raw-сокетов:

| Что | Как |
|---|---|
| Узел жив | системный `ping` или TCP connect к набору портов; ответ «порт закрыт» тоже считается — узлы с запрещённым ping не теряются |
| Hostname | обратный DNS, иначе NetBIOS-имя |
| MAC | NetBIOS-запрос (работает и через маршрутизатор для Windows), иначе ARP-кэш ОС (только свой сегмент) |
| Производитель | по OUI из MAC |
| Тип | открытые порты + баннер SSH + заголовок `Server:` HTTP + производитель: ESXi, Proxmox, Windows, Linux (с дистрибутивом), принтер, камера, NAS, Cisco/MikroTik, ВМ VMware/Hyper-V/KVM… Причины записываются в JSON (`type_reasons`) |

Данные vSphere и сети объединяются по IP: у ВМ из vCenter появляются реальные открытые порты,
у найденных в сети узлов — имя ВМ и ОС.

**Справочник производителей.** Встроен небольшой (VMware, Hyper-V, KVM, VirtualBox, Xen, Cisco,
Raspberry Pi, Synology). Для полного положите рядом с `main.py` файл Wireshark
[`manuf`](https://www.wireshark.org/download/automated/data/manuf) или IEEE `oui.txt`, либо укажите
путь в переменной `INVENTORY_OUI_FILE`, либо `pip install manuf`.

## Отчёты

- **JSON** — всё: настройки задания (без пароля), данные vSphere, параметры и итоги сканирования,
  устройства со всеми полями (порты, баннеры, NetBIOS, причины типа), ошибки и предупреждения.
- **CSV** — таблица устройств; UTF-8 с BOM и разделителем `;`, чтобы Excel с русской локалью открыл
  без мастера импорта. Значения, начинающиеся с `= + - @`, экранируются (защита от формул в именах из сети).
- **Markdown** — читаемый отчёт: итоги, типы устройств, ошибки, хосты, ВМ, хранилища, устройства.

## Ошибки

| Ситуация | Что видно |
|---|---|
| Неверный логин/пароль | красный индикатор «Неверный логин или пароль» |
| vCenter недоступен / имя не найдено в DNS | «vCenter … недоступен: Connection refused» / «Имя … не найдено» |
| vCenter завис (соединение принято, ответа нет) | таймаут, а не вечное ожидание |
| Сертификат не прошёл проверку | подсказка выключить проверку или добавить CA |
| Таймаут сканирования | задание завершается с найденным, предупреждение «проверено N из M» |

Ошибка vCenter не отменяет сканирование подсетей, и наоборот — всё попадает в раздел ошибок отчёта.

## Журнал и настройки

Все действия пишутся в файл (ротация 5 × 2 МБ), пароль — никогда:

| ОС | Журнал | Настройки (без пароля) |
|---|---|---|
| Windows | `%LOCALAPPDATA%\InfraInventory\logs\inventory.log` | `%LOCALAPPDATA%\InfraInventory\settings.json` |
| Linux | `~/.local/state/infra-inventory/inventory.log` | `~/.config/infra-inventory/settings.json` |
| macOS | `~/Library/Logs/InfraInventory/inventory.log` | `~/Library/Application Support/InfraInventory/settings.json` |

Путь к журналу показан в окне; другой можно задать ключом `--log-file`.

## Без окна (для планировщика)

```bash
# пароль — из переменной окружения или будет запрошен
INVENTORY_VC_PASSWORD=... python main.py --cli --vcenter vc.local --user ro@vsphere.local \
    --subnet 10.0.0.0/24 --subnet 10.0.1.1-100 --out D:\reports
python main.py --cli --no-vsphere --subnet 192.168.1.0/24 --formats csv,md
```
Код возврата: 0 — без ошибок, 1 — были ошибки (отчёт всё равно сохранён), 2 — неверные параметры.

## Структура

| Файл | Назначение |
|---|---|
| `main.py` | точка входа: журнал, папки, окно или консольный режим |
| `gui.py` | интерфейс (ZePyGUI) |
| `vsphere_client.py` | подключение к vCenter, сбор данных, тестовый vCenter `mock` |
| `network_scanner.py` | сканирование подсетей, MAC, производители, типы устройств |
| `inventory.py` | задание: vSphere + сеть + объединение (общее для окна и консоли) |
| `exporter.py` | JSON, CSV, Markdown |
| `tests/` | тесты |

## Проверка

```bash
python -m unittest discover -s tests -v     # Windows/macOS/Linux
tests/run_tests.sh                          # Linux под root: + тестовая подсеть с имитацией устройств
```

- Тестовый vCenter: адрес `mock` (пароль `wrong` — ошибка входа, `mock-timeout` — таймаут, `mock-down` — недоступен).
- Ошибки настоящего pyvmomi проверяются на локальных «плохих» серверах (закрытый порт, молчащий сервер).
- Тестовая подсеть `127.0.0.11–14`: Linux с SSH, Windows с NetBIOS, принтер, ESXi — проверяются MAC,
  производитель, имя и тип. `run_tests.sh` запускает её в отдельном сетевом пространстве имён: ни
  одного пакета в реальную сеть.
- Настоящий pyvmomi против симулятора vCenter (vcsim):
  `docker run -d -p 127.0.0.1:8989:8989 vmware/vcsim:v0.52.0 -l 0.0.0.0:8989 -username u -password p`,
  затем `VCSIM_URL=127.0.0.1:8989 VCSIM_USER=u VCSIM_PASSWORD=p python -m unittest tests.test_inventory.TestVcsim`.
- Окно в настоящем браузере: `tests/run_gui_test.sh` (Linux + Docker) — подключение с неверным и верным
  паролем, долгое сканирование (окно отвечает быстрее 1 с, таблица заполняется), остановка, задание
  до конца, фильтр, выгрузка, скриншоты.
