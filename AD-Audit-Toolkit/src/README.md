# Сбор данных Active Directory в JSON

Программа подключается к контроллеру домена, собирает структуру AD и сохраняет её в один JSON —
основу для второго приложения (создание пользователей):

- **дерево OU** с иерархией (родитель → потомки), описаниями и числом объектов в каждой OU;
- **пользователи** — все атрибуты из задания и ещё ~40 полезных (UPN, включена/отключена, SID, GUID, основная группа…);
- **группы** — с участниками (в том числе группы больше 1500 участников), типом и областью действия;
- **компьютеры** — имя, DNS-имя, ОС, последний вход, контроллер ли домена;
- **площадки** — из OU площадок (`Площадки`, `Филиалы`, `Sites`…) или, если таких OU нет, из поля «Офис» пользователей;
- **должности** и **отделы** — уникальные значения с числом сотрудников;
- для второго приложения: **суффиксы UPN**, **политика паролей**, NetBIOS-имя домена, контейнеры по умолчанию,
  **сайты AD** с подсетями, групповые политики, контакты.

Нужен только Python 3.10+ и библиотека `ldap3`. Права администратора не нужны — ни на компьютере, ни в домене.

## Установка и запуск

```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate          Linux:  source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

На Windows `tkinter` входит в Python с python.org. На Linux его иногда ставят отдельно:
`sudo apt install python3-tk` (Debian/Ubuntu), `sudo dnf install python3-tkinter` (Fedora/RHEL).

**Попробовать без AD:** `python main.py --demo` — подставит тестовый домен `demo.local` в памяти
(адрес `mock`): нажмите «Подключиться», затем «Собрать данные».

## Как пользоваться

1. **Контроллер домена** — имя DC (`dc01.company.local`), IP-адрес или просто имя домена (`company.local`).
   Можно с портом: `dc01:636`.
2. **Логин** — `КОМПАНИЯ\ivanov` или `ivanov@company.local` (можно просто `ivanov` — домен
   определится сам). **Пароль**.
3. **Защита** — оставьте «Авто»: программа пробует LDAPS (636), затем StartTLS (389), затем — только для логина
   вида `ДОМЕН\user` — NTLM без шифрования канала (пароль по сети не передаётся). Простой пароль открытым текстом
   программа сама не отправляет никогда — только если явно выбрать «Без шифрования».
   «Проверять сертификат» включайте, если сертификат DC выдан доверенным центром (на Windows берутся
   корневые сертификаты системы).
4. **Подключиться** — индикатор: серый — не подключено, жёлтый — подключение, зелёный — подключено
   (с именем DC и режимом), красный — ошибка с понятной причиной.
5. **Собрать данные** — прогресс-бар и журнал в реальном времени; окно не зависает (работа в фоновом потоке).
   «Остановить» прерывает сбор — собранное можно сохранить, в JSON оно будет помечено как неполное.
   **OU площадок** — заполните, только если площадки лежат в OU с необычным названием (имя или DN).
6. **Сохранить JSON** — выбор файла; имя по умолчанию `ad_structure_<домен>_<дата>_<время>.json`.

После сбора на вкладках видны дерево OU и списки площадок, должностей, отделов и сайтов AD.

### Какие права нужны учётной записи

**Достаточно обычного пользователя домена** (группа «Пользователи домена» / Domain Users) — по умолчанию
все прошедшие проверку пользователи могут читать OU, пользователей, группы, компьютеры, сайты и политику
паролей. Рекомендуется отдельная учётная запись, например `svc-ad-reader`:

- член только «Пользователи домена», никаких административных групп;
- «Срок действия пароля не ограничен» (если сбор будет по расписанию);
- при желании — запрет интерактивного входа на компьютеры через групповую политику.

Права на запись не нужны и не используются: программа открывает соединение только для чтения.
Если в домене ограничили чтение (например, скрыли OU или атрибуты), недоступное просто не попадёт в JSON,
а недоступные разделы будут перечислены в `scan_info.warnings`.

### Защищённое подключение

- **LDAPS / StartTLS** работают, если у контроллера домена есть сертификат (обычно выдаётся AD CS автоматически).
- Если сертификата нет, а DC требует подписи LDAP («LDAP server signing requirements = Require signing»),
  вход по NTLM без шифрования будет отклонён — программа скажет об этом и предложит LDAPS.
- Учтите: NTLM-вход проверен только на уровне вычисления хеша (тестовый DC Samba этот способ входа не поддерживает,
  см. «Проверка»). Основной и проверенный путь — LDAPS/StartTLS.

## Что в JSON

Формат — как в задании, плюс дополнительные поля (их можно не использовать):

| Раздел | Содержимое |
|---|---|
| `scan_info` | домен, NetBIOS-имя, адрес и имя DC, дата сбора, длительность, режим подключения, итоги, `status` (`complete` / `cancelled` / `failed`), `errors`, `warnings` |
| `domain` | DN, SID, функциональный уровень, `upn_suffixes`, `password_policy` (длина, сложность, срок, блокировка), `well_known_containers` (куда AD кладёт новых пользователей и компьютеры), `machine_account_quota` |
| `ou_tree` | `{dn, name, description, children}` + `path` («Площадки/Площадка-А/Производство»), `counts` (пользователи/группы/компьютеры прямо в OU), `gpo_links` |
| `users` | поля из задания (`office` = атрибут `physicalDeliveryOfficeName`, `dn` = `distinguishedName`) + `userPrincipalName`, `enabled`, `locked`, `uac_flags`, `ou`, `ou_path`, `primaryGroup`, `manager_sAMAccountName`, `mobile`, `employeeID`, `city`, `objectSid`, `objectGUID`, `pwdLastSet`, `mustChangePassword`, `accountExpires`, `extensionAttributes`… |
| `groups` | поля из задания (`members` = атрибут `member`, `groupType` — строкой, как в примере) + `category` (`security`/`distribution`), `scope` (`global`/`domain_local`/`universal`), `member_count`, `objectSid`, `rid`, `ou_path` |
| `computers` | поля из задания + `enabled`, `is_domain_controller`, `operatingSystemServicePack`, `ou_path`… |
| `offices` | список названий площадок; `offices_detail` — откуда взяты (`source`: `ou` или `physicalDeliveryOfficeName`), число сотрудников и отделы каждой площадки, а также значения поля «Офис» |
| `positions` | уникальные должности; `positions_detail` — с числом сотрудников |
| `departments`, `companies` | уникальные отделы и организации |
| `ad_sites` | сайты AD (Сайты и службы) с подсетями и контроллерами домена |
| `contacts`, `containers`, `gpos` | контакты, контейнеры верхнего уровня (`CN=Users`…), групповые политики |
| `attribute_map` | соответствие ключей JSON атрибутам AD (`office` → `physicalDeliveryOfficeName`…) |

Время — ISO 8601 в UTC (`2026-10-12T08:15:00+00:00`), пустое и «никогда» — `null`.
Файл в UTF-8, кириллица без экранирования. В JSON нет паролей, но есть персональные данные
сотрудников — храните его соответственно.

**Учтите при создании пользователей:** основная группа (обычно «Пользователи домена») в AD не входит в
`memberOf` и `members` — она в поле `primaryGroup`.

## Как проверить результат

1. В окне: `статус` «Готово», числа в карточках (OU, пользователи, группы, компьютеры) похожи на ожидаемые.
2. В JSON: `scan_info.status` = `"complete"`, `scan_info.errors` пуст.
3. Сверьте количества с AD (PowerShell на компьютере с RSAT):

   ```powershell
   (Get-ADUser -Filter *).Count                 # = scan_info.total_users
   (Get-ADGroup -Filter *).Count                # = scan_info.total_groups
   (Get-ADOrganizationalUnit -Filter *).Count   # = scan_info.total_ous
   (Get-ADComputer -Filter *).Count             # = scan_info.total_computers
   ```

4. Быстрый просмотр в Python:

   ```python
   import json
   d = json.load(open("ad_structure_company.local_....json", encoding="utf-8"))
   print(d["scan_info"]["status"], d["scan_info"]["total_users"])
   print(d["offices"], d["positions"], sep="\n")
   ```

## Ошибки

| Ситуация | Что видно |
|---|---|
| Неверный логин или пароль | «Неверный логин или пароль» (а также: учётная запись заблокирована / отключена / истёк пароль / нужно сменить пароль) |
| DC недоступен | «Контроллер домена … недоступен: соединение отклонено» / «Имя … не найдено в DNS» |
| Таймаут | «Контроллер домена … не ответил вовремя» — без вечного ожидания (таймаут настраивается в окне) |
| DC требует подписи LDAP | подсказка выбрать LDAPS или войти как `ДОМЕН\пользователь` |
| Сертификат не прошёл проверку | подсказка выключить проверку или установить корневой сертификат домена |
| Связь пропала во время сбора | сбор останавливается, собранное можно сохранить (`status: failed`, причина в `errors`) |

Пустой пароль программа не принимает: AD считает такой вход анонимным.

## Журнал и настройки

Все действия пишутся в файл (ротация 5 × 2 МБ), пароль — никогда:

| ОС | Журнал | Настройки (без пароля) |
|---|---|---|
| Windows | `%LOCALAPPDATA%\ADCollector\logs\ad_collector.log` | `%LOCALAPPDATA%\ADCollector\settings.json` |
| Linux | `~/.local/state/ad-collector/ad_collector.log` | `~/.config/ad-collector/settings.json` |

Путь к журналу показан внизу окна; другой — ключом `--log-file`.

## Без окна (для планировщика)

```bash
# пароль — из переменной AD_PASSWORD или будет запрошен
AD_PASSWORD=... python main.py --cli --dc dc01.company.local --user "COMPANY\svc-ad-reader" --out D:\ad\
python main.py --cli --demo --out .        # демо-домен
```

Ключи: `--security auto|ldaps|starttls|plain`, `--verify-cert`, `--timeout`, `--offices-ou`, `--base-dn`.
Код возврата: 0 — собрано полностью, 1 — ошибка или неполные данные (JSON всё равно сохранён), 2 — неверные параметры.

## Структура

| Файл | Назначение |
|---|---|
| `main.py` | точка входа: журнал, окно или консольный режим |
| `gui.py` | окно (tkinter) |
| `ad_client.py` | подключение к DC: LDAPS/StartTLS/NTLM, понятные ошибки |
| `collector.py` | сбор данных (постраничный поиск), сборка и сохранение JSON |
| `mock_ad.py` | тестовый домен в памяти для демо-режима и тестов |
| `tests/` | тесты |

Постраничный поиск (`paged search`, по 500 записей) обходит лимит AD в 1000 записей; участники групп больше
1500 человек дочитываются по частям (`member;range=…`) автоматически.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Без сети и без AD (25 тестов):
- преобразования (время Windows, SID, GUID, флаги учётных записей, DN с запятыми, MD4 для NTLM);
- тестовый домен в памяти: формат JSON из задания, 1101 пользователь (3 страницы), дерево OU, площадки,
  должности, остановка, площадки из атрибута;
- `tests/fake_ad_server.py` — LDAP-сервер с ограничениями настоящего AD: без постраничного поиска отдаёт только
  1000 записей из 2500, большую группу (3200 участников) — кусками по 1500; программа получает всех;
- ошибки: неверный пароль, закрытый порт, «молчащий» сервер (таймаут), имя не в DNS.

С настоящим контроллером домена:
```bash
AD_TEST_DC=dc01.company.local AD_TEST_USER='COMPANY\svc-ad-reader' AD_TEST_PASSWORD=... \
    python -m unittest tests.test_ad_collector.TestRealDC -v
```

Проверено на **Samba AD DC** (совместим с AD по LDAP) в Docker — `tests/samba/`:
```bash
docker build -t ad-collector-test tests/samba
docker run -d --name adtest --hostname dc01 --cap-add SYS_ADMIN -p 127.0.0.1:1636:636 ad-collector-test
python tests/samba/seed.py > seed.ldif && docker cp seed.ldif adtest:/ && docker exec adtest ldbadd -H /var/lib/samba/private/sam.ldb /seed.ldif
docker exec adtest samba-tool user create ro.reader 'R3ad-only!pass'
AD_TEST_DC=127.0.0.1:1636 AD_TEST_USER='COMPANY\ro.reader' AD_TEST_PASSWORD='R3ad-only!pass' AD_TEST_SEEDED=1 \
```

для чтения — обычный пользователь домена. Окно проверено `tests/gui_test.py` под Xvfb (21 проверка: ошибки
входа, сбор, отзывчивость окна, остановка, сохранение, отсутствие пароля в журнале и настройках).
